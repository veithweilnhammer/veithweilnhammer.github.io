# Communication strategy

This directory is the small strategic layer above the website and the existing
blog workflow. It answers four questions: what Veith's research programme is,
what deserves attention now, which strong ideas are worth retaining, and which
decisions have already been made.

| File | Purpose |
|---|---|
| [positioning.md](positioning.md) | The durable public identity and language that should connect the work. |
| [pipeline.md](pipeline.md) | A selective opportunity queue plus the baseline assessment of existing drafts. |
| [content.md](content.md) | A curated bank of undeveloped ideas with strong programme fit. |
| [log.md](log.md) | Terse record of consequential strategic decisions. |

## Working agreement

Veith updates real-world facts that only he can confirm: commitments, target
dates, external invitations, publication decisions, and final approval to ship.
Draft prose continues to live in [blog/content](../blog/content), which is the
source of truth described in [the blog workflow](../blog/README.md). Publication
metadata continues to live in [_bibliography/papers.bib](../_bibliography/papers.bib).

During our conversations, I keep `pipeline.md` current when status or next
actions change, add only high-potential ideas to `content.md`, revise
`positioning.md` only when the programme framing changes, and add to `log.md`
only when we make a meaningful decision.

For the 21 essays represented in both `blog/content/` and `_drafts/`, edit the
`blog/content/` copy. The five short research or teaching pieces that exist only
in `_drafts/` are tracked separately in the pipeline. No additional planning
files should be added unless these four documents can no longer hold the work.

## Channel roles

- **Research hubs** hold the evidence: paper, methods, data, code, and
	interactive results. They should not be duplicated as blog posts.
- **The website** is the canonical home for essays and the map of the broader
	research programme. Substantive pieces should live here first.
- **LinkedIn** is the main distribution and discussion channel. Each post
	should make one native argument for one audience, then point to the relevant
	essay, paper, or explorer when useful.
- **Substack is deferred.** Revisit it when building an email relationship is a
	deliberate goal and there is a sustainable digest or newsletter cadence. If
	activated, use it to send readers to canonical website pieces rather than
	maintaining a second full archive.
